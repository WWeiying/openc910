# C910 VFPU 总体架构详细教学文档

> 主要 RTL：
> - `C910_RTL_FACTORY/gen_rtl/vfpu/rtl/`
> - `C910_RTL_FACTORY/gen_rtl/vfalu/rtl/`
> - `C910_RTL_FACTORY/gen_rtl/vfmau/rtl/`
> - `C910_RTL_FACTORY/gen_rtl/vfdsu/rtl/`

本文先说明当前生成 RTL 实际具备的能力，再解释文件中保留的向量化命名和模板。
这是阅读 VFPU 的必要前提：模块叫作 VFPU，不等于当前配置已经实现 RVV。

## 1. 当前配置到底实现了什么

当前有效路径是一组 64 位标量浮点执行单元，覆盖浮点加减、比较、符号操作、
分类、转换、乘法、乘加、除法和开方。下列 RTL 事实共同限定了能力边界：

| 证据 | 有效逻辑 | 可以得到的结论 |
|---|---|---|
| ISA 声明 | `ct_cp0_regs.v`：`misa_vector = 1'b0` | 软件不可见 RISC-V Vector 扩展 |
| 指令译码 | `ct_idu_id_decd.v`：`x_vec_inst = 1'b0` | 当前译码不会产生有效向量指令 |
| 物理状态表 | RTU 实例化 `ct_rtu_pst_vreg_dummy` | 当前没有有效向量物理寄存器生命周期管理 |
| VFPU 写回 | RBus 的 VR 写有效和 VR0/VR1 数据固定为 0 | 当前 VFPU 不向向量寄存器数据体写回 |
| VFDSU 实例 | 一个 64 位 `ct_vfdsu_double` + `ct_vfdsu_scalar_dp` | 当前除法/开方是单个标量实例 |
| VFMAU 实例 | `ct_vfmau_top` 只实例化 `slice0` | 当前没有第二个 64 位 slice 拼成 128 位 |

源码中的 `vreg` 是历史/可配置代码基线沿用的七位目的寄存器编码名称。当前 RBus
用其最高位区分寄存器类别；当最高位为 0 时，结果写入浮点物理寄存器路径。
因此，看到 `dst_vreg` 不能直接解释为“目的向量寄存器”。

`vlenb_value=16`、`VLEN=128` 参数、`vr0/vr1` 端口以及注释中的 set0/set1、
slice0/slice1，说明代码保留了向量化接口或生成模板。由于当前有效译码、状态表、
实例和写回均未形成完整向量链路，这些残留不能提升为当前配置的功能结论。

## 2. VFPU 在后端中的位置

IDU 通过 pipe6 和 pipe7 两组 RF 接口向 VFPU 送入选择、功能码、源数据、IID 和
目的寄存器编码。VFPU 内部把一次操作分成四类信息：

1. **指令身份**：IID 随 CBUS 返回 RTU，用于命中对应 ROB 项；
2. **执行控制**：`eu_sel`、`func`、精度和舍入模式决定启动哪个子单元；
3. **结果数据**：64 位浮点结果经 RBus 写回浮点物理寄存器；
4. **异常状态**：5 位 EREG 数据经独立写回路径保存，之后参与精确异常/`fflags`
   相关处理。

需要严格区分这些事件，而且不能把它们画成一条“执行结束后依次发生”的直线：

```text
                         -> CBUS 寄存一级 -> RTU/ROB 完成记账
IDU 选择有效 -> 分叉
                         -> 子单元执行 -> RBus 数据/异常写回

ROB 再综合完成记账、顺序、异常及相关资源状态决定是否退休
```

CBUS 与执行数据路径从 IDU 选择处分叉；它不是子单元算完后发出的脉冲。对
VFDSU 这样的长延迟单元，CBUS 事件会远早于最终结果返回。`cmplt` 的名字表示
RTU/ROB 接口上的完成记账事件，不等价于算术运算结束、结果已经写入寄存器，
更不等价于指令已经退休。

## 3. 顶层组件

`ct_vfpu_top` 主要负责实例化和接线，运算逻辑位于子模块中：

| 组件 | 当前职责 |
|---|---|
| `ct_vfpu_ctrl` | 生成 pipe6/pipe7 的 EX1~EX5 有效位、级间控制和门控时钟 |
| `ct_vfpu_dp` | 锁存操作数和目的信息，压缩 EU 选择，汇聚固定/变延迟结果 |
| `ct_vfpu_cbus` | 把 IDU 选择和 IID 寄存一拍后形成 RTU 完成接口 |
| `ct_vfpu_rbus` | 形成浮点物理寄存器、EREG 写回和 IDU 前递/唤醒广播 |
| `ct_vfalu_top_pipe6/7` | 加减、比较、特殊位操作；pipe7 另含转换 |
| `ct_vfmau_top_pipe6/7` | 每条管线一个标量 slice0 乘法/乘加单元 |
| `ct_vfdsu_top` | pipe6 独有的单个标量除法/开方单元 |

`ct_vfpu_ctrl` 和 `ct_vfpu_dp` 都有 EX1~EX5 级名，是为了容纳不同就绪阶段的
指令。某个子单元只经过 EX1~EX3，并不表示其结果立即退休；EX3 之后仍可能经过
顶层汇聚、RBus 寄存和 RTU 的顺序退休判断。

## 4. pipe6 与 pipe7：相似接口，不是完全对称

两条入口都能运行 fadd/fspu 和 vfmau，但有三处重要差异：

| 机制 | pipe6 | pipe7 |
|---|---|---|
| fadd/fspu | 有 | 有 |
| fcnvt | 无有效实例 | 有 |
| vfdsu | 唯一实例挂在 pipe6 | 无 |
| 变延迟返回注入 | 有 VFDSU/保留 VDIV 返回槽 | 无对应 VFDSU 槽 |
| 局部 EU 压缩编码 | 5 位，包含返回注入位 | 4 位，不含 pipe6 的返回位 |

因此，“双浮点管线”准确表示有两组发射入口和两份常用执行资源；它不表示任意两条
浮点指令都能对称地放到任意端口。例如转换要去 pipe7，除法/开方要去 pipe6。

## 5. EU 选择如何分发

IDU 给出 12 位 `idu_vfpu_rf_pipe*_eu_sel`。当前标量浮点路径中的有效映射为：

| 位 | 当前用途 | 配置边界 |
|---|---|---|
| `[0]` | fspu | pipe6、pipe7 |
| `[1]` | fadd | pipe6、pipe7 |
| `[2]` | fcnvt | 仅 pipe7；pipe6 送入 VFALU 的该位固定为 0 |
| `[3]` | vfdsu 请求槽 | 仅 pipe6 |
| `[4]` | vfmau | pipe6、pipe7 |
| `[10:5]` | 保留 VDSP/向量类槽 | pipe6 会把它们压成局部来源 bit3，但没有 VDSP 实例；pipe7 的对应局部来源 bit3 直接固定为 0 |
| `[11]` | 保留 VDIV 类槽 | 当前 VDIV 返回、busy 和结果有效均固定为 0；向量译码关闭后也不会形成合法请求 |

`ct_vfpu_dp.v` 在 pipe6 将 12 位压成五类：

```verilog
eu_sel_pre[0] = |eu_sel[2:0];              // VFALU 组
eu_sel_pre[1] = eu_sel[3] || eu_sel[11];   // FDSU/保留 VDIV 请求组
eu_sel_pre[2] = eu_sel[4];                 // FMAU
eu_sel_pre[3] = |eu_sel[10:5];             // 保留 VDSP/向量组
eu_sel_pre[4] = vfdsu_return || vdiv_return;// 变延迟结果重新注入
```

这不是另一套指令译码，而是级间结果来源编码。特别是 bit4 表示“返回结果现在被
注入固定流水”，不是原始指令又发射了一次。

pipe7 的压缩关系并非 pipe6 的简单删减版：虽然它仍保留
`eu_sel_pre[1] = eu_sel[3] || eu_sel[11]` 这类历史请求归类，局部 bit3 却明确
赋为 0，也没有 VFDSU/VDIV 返回注入位。正常运行依赖上游只向 pipe7 发送该端口
实际具备的 VFALU/VFMAU 操作；这些保留编码不能当作隐藏的可执行资源。

## 6. 三类执行路径

### 6.1 VFALU：短流水组

VFALU 包含 fadd、fspu 和 fcnvt。三者各自有控制与数据子模块，并非物理共用一组
内部寄存器。它们使用对齐的 EX1~EX3 协议，由一热选择互斥启动，结果在
`ct_vfalu_dp_pipe6/7` 汇聚。因此准确说法是：

> 三个独立子算子共享同一发射时隙和汇聚/写回资源，而不是共用同一个算术流水体。

pipe6 只实例化 fadd/fspu；pipe7 还实例化 fcnvt。汇聚 mux 的 default 为 `X`，
说明正常设计依赖上游产生合法的一热选择；这个 mux 本身不是一热错误检查器。

### 6.2 VFMAU：深流水组

pipe6 和 pipe7 各实例化一个 `ct_vfmau_top`，每个顶层当前只有一个
`ct_vfmau_mult1` 的 `slice0` 实例。它包含 Booth/部分积压缩、乘积与加数对齐、
加法、LZA/规格化、舍入和打包等阶段。

EX1~EX5 是结构级。不同操作可以在不同阶段形成可前递或可写回数据，所以不能把
“五级结构”简化成所有乘法/FMA 都在同一个固定点对所有消费者可见。是否能连续
接收新操作还受 IDU 调度、数据依赖、写回冲突和 flush 影响。

### 6.3 VFDSU：单个迭代组

VFDSU 只挂 pipe6。其 SRT 状态机重复更新同一组余数/商根状态，因此当前单实例
占用期间不能接收另一条除法/开方操作。`vfdsu_dp_fdiv_busy` 表示状态机编码中的
忙区间，`vfdsu_dp_inst_wb_req` 是结果接近写回时对共享写回时隙的申请；二者用途
不同，不能互换。

单实例是 RTL 事实。至于“为什么只做一份”可以从长延迟、迭代状态和硬件成本推断
为面积/吞吐折中，但“除法一定低频”“复制一定不划算”需要工作负载和综合数据，
不是该 RTL 本身能够证明的事实。

## 7. CBUS：完成事件，不是数据写回

pipe6 的核心逻辑为：

```verilog
cbus_pipe6_cmplt = idu_vfpu_rf_pipe6_sel;
cbus_pipe6_inst_vld <= cbus_pipe6_cmplt;
vfpu_rtu_pipe6_cmplt = cbus_pipe6_inst_vld;
```

准确的时序描述是：IDU 的 RF 选择在时钟沿被 CBUS 有效位寄存器采样，寄存器输出
阶段向 RTU 形成 `vfpu_rtu_pipe6_cmplt`；IID 由单独的门控数据时钟在对应选择时
采样。不能写成“组合地在发射当拍直接送到 RTU”。

更重要的是，CBUS 没有按 `eu_sel` 排除 VFDSU。只要
`idu_vfpu_rf_pipe6_sel=1`，该选择就进入 CBUS。因此“VFDSU 不走 CBUS、等待最终
结果后才报完成”与当前 RTL 不符。

RTU 使用 `cmplt + iid` 命中 ROB 项并更新完成状态；浮点物理寄存器表和 EREG
又分别跟踪写回与退休。由此可见，该接口允许 ROB 完成记账与结果资源就绪分离。
是否在某一拍真正退休仍由 ROB 头位置、异常、同步/flush 等条件共同决定。

## 8. RBus：结果、异常、唤醒与前递

RBus 汇集 VFALU、VFMAU 和 VFDSU 注入后的数据。当前有效写回分为：

- 64 位浮点物理寄存器数据；
- 5 位 EREG 浮点异常结果；
- 目的寄存器编码及其展开掩码；
- 给 IDU 的就绪、前递和写回广播。

RBus 中大量 `_dup0...` 信号是显式复制链。根据其连接方式和广播用途，将其解释为
降低单一逻辑节点扇出、服务不同消费者是合理的微结构解释；但未结合综合网表和
时序报告时，不应进一步声称某条复制链已经解决了具体关键路径。

当前 `rbus_pipe*_vreg_vr_wb_vld` 固定为 0，VR0/VR1 写回/前递数据固定为 0；
`rbus_pipe*_vreg_fr_wb_vld` 在目的编码最高位为 0 时有效。也就是说，名称保留
“vreg”，当前有效数据落点却是浮点物理寄存器分支。

## 9. MTVR/MFVR 与保留向量接口

整数侧有 MTVR/MFVR 命名的接口，VFPU 也能把 IU 的 EX1 控制和 EX2 数据注入
短流水。它们来自向量化代码基线，但在当前配置中应按实际接线理解为整数侧与
浮点寄存器/浮点数据通路之间的搬移或早出结果接口，不能仅凭名称认定为完整
向量寄存器访问。

MTVR 控制先到、源数据后一阶段到，是两个流水级之间的对齐关系。分析波形时应把
`iu_vfpu_ex1_*_mtvr_vld/inst` 与下一阶段 `iu_vfpu_ex2_*_mtvr_src0` 配对，
不能要求控制和数据在同一周期同时有效。

## 10. Flush 与门控时钟的精确含义

顶层 VFPU 控制有效位和 RBus 写有效在 `rtu_yy_xx_flush` 时清零。VFMAU 也有
逐级 flush；VFALU 的三个局部 ctrl 没有 flush 端口。因此：

- 顶层会阻止被冲刷指令以有效结果进入共享写回/退休路径；
- VFALU 内部局部数据或 `pipedown` 仍可能走完已有短流水；
- 在没有把所有内部观察点和副作用都追踪完之前，不应笼统写成“内部立即清空”
  或“内部继续计算绝对没有任何活动”。

`gated_clk_cell.local_en=0` 表示本地逻辑没有提出开钟请求，不等于输出时钟在所有
模式都必然停止。`global_en`、`module_en` 和 `pad_yy_icg_scan_en` 仍参与门控。
有些有效位时钟把“当前级或下一级仍有效”并入 `local_en`，目的是既能装入 1，
也能在尾部流出后装回 0；所以不能一概写成“只有新指令到来时才开钟”。

## 11. 如何阅读延迟和吞吐

| 观察对象 | RTL 能直接证明什么 | 不能直接推出什么 |
|---|---|---|
| VFALU | 选择在 EX1 启动，局部有效位传播到 EX3 | 从 IDU 发射到体系结构退休恰好三拍 |
| VFMAU | 控制/数据具有 EX1~EX5 结构和多个前递点 | 任意 FMA 在任意数据模式下都能每拍接收 |
| VFDSU | 计数初值为 13/6/3，可提前结束，单实例忙时串行 | 初值本身就是迭代次数或完整端到端延迟 |
| CBUS | IDU 选择寄存后产生带 IID 的 RTU 完成事件 | 数据已写回、异常已提交或指令已退休 |
| RBus | 某阶段对 FREG/EREG 产生写有效 | 该周期一定改变体系结构可见状态 |

对 VFDSU，计数器启动时装入 N，随后在 busy 状态逐拍递减，并在当前值为 0 时触发
正常结束。因此不提前结束时会经历 N、N-1、...、0，共 N+1 个有效计数状态：
double/single/half 分别是 14/7/4。再叠加发射、状态转换、round、pack 和返回注入，
才得到某个明确定义参考点之间的端到端延迟。

## 12. 体系结构理解

VFPU 最值得学习的不是“若干运算分别几拍”，而是乱序核如何把不同生命周期的
执行单元接到同一后端：

- 短流水通过固定阶段和前递隐藏依赖；
- 深流水通过多级前递和结果阶段选择减少消费者等待；
- 迭代单元通过 busy 阻止资源重入，通过写回申请抢占共享返回槽；
- CBUS 把 ROB 完成记账与数据写回解耦；
- 物理浮点寄存器表、异常状态表和 ROB 分别管理数据、异常和程序顺序。

这种解耦提高了并行度，也提高了验证难度。波形分析时，至少要同时观察 IID、
EU 选择、局部有效位、目的物理寄存器、数据写有效、EREG 写有效、CBUS 完成和
ROB 退休，不能只凭任一条 `valid` 判定一条指令“已经完成全部生命周期”。
