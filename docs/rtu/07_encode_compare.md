## 1. ct_rtu_compare_iid：环形空间的年龄裁判

### 1.1 问题

IID = {1 位 wrap, 6 位 ROB 索引}，分配指针环形递增。"谁更老"不能直接比大小：
wrap 翻转后，数值小的反而更新。

### 1.2 实现（compare_iid.v:42-78）

```verilog
assign iid_msb_mismatch = x_iid0[6] ^ x_iid1[6];          // wrap 是否同圈

// 低 6 位逐位"谁在更高位先胜出"——这是一个展开的无符号比较器
assign iid0_larger[k] = x_iid0[k] && !x_iid1[k];
assign iid0_5_0_larger = iid0_larger[5]
                      || iid0_larger[4] && !iid1_larger[5]
                      || ...;                              // 高位优先

assign x_iid0_older = !iid_msb_mismatch && iid1_5_0_larger   // 同圈: 小者老
                   ||  iid_msb_mismatch && iid0_5_0_larger;  // 异圈: 大者老
```

规则一句话：**同圈比大小（小=老），异圈反着比（大=老）**。

正确性前提不是笼统的“机器里在飞指令不超过 64 条”，而是：参与比较的两个
**有效 IID** 必须位于同一个 64 项 ROB 活跃窗口内，使模 128 年龄关系不会产生
半圈歧义。ROB 创建、退休与 full 控制共同维护这一使用约束。折叠会让一个 IID
代表多条架构指令，但不会扩大 IID 的 ROB 项距离。

RTL 没有写成 `(iid0 - iid1)`，而是显式展开低 6 位的高位优先比较，再结合
wrap 位选择同圈/异圈规则。这样写明确暴露了逻辑意图，也便于在多处复用；但不能
仅凭 RTL 表达式断言综合后“一定是 6 级”或“一定比减法器更快”。综合器可能重构
布尔网络，真实面积、门级深度和时序必须由目标工艺与综合报告确认。

当两个 IID 完全相等时，低 6 位不存在任一方更大，`x_iid0_older` 为 0。
因此该输出表达的是严格的 “iid0 比 iid1 老”，不是 “更老或相等”。

## 2. encode / expand：两种编码的互换

```
expand_N : log2(N) 位二进制 → N 位独热    （译码器）
encode_N : N 位独热 → log2(N) 位二进制    （编码器）
```

这里的 `encode_N` 是逐项常数掩码后按位 OR 的**普通 one-hot 编码器**，不是
优先编码器，也没有额外的 valid/error 输出：

```verilog
x_num = (bit0 ? 0 : 0) | (bit1 ? 1 : 0) | ...;
```

它只在输入满足 one-hot 协议时具有唯一、直观的索引含义。两个边界行为尤其要注意：

- 输入全 0 时，输出也是 0，因此仅看 `x_num==0` 无法区分“选中 entry0”和
  “没有任何项被选中”；消费者必须同时使用上游 valid。
- 输入多热时，输出是所有有效索引的**逐位 OR**，不是最低索引或最高索引。例如
  bit1 与 bit2 同时为 1 会编码成 `3`。这通常是协议违例，不能把结果解释成
  entry3 被选中。

`expand_8/32/64` 的二进制输入覆盖完整编码空间，输入无 X 时恰有一位为 1。
`expand_96` 使用 7 位输入，但只实现索引 0~95；输入 96~127 时输出全 0。这种
全零同样需要由上游 `_vld` 屏蔽，不能单独当成合法的“空寄存器号”。仿真输入
含 X/Z 时，等值比较还可能把 X 传播到独热输出，应先检查驱动有效性。

C910 在指针/标识上**两种编码并存、按消费场景选用**：

| 场景 | 用哪种 | 原因 |
|------|--------|------|
| 环形指针步进 | 独热 | 移位即 +1，无进位链（PCFIFO/ROB 的 create/pop ptr） |
| 读/写口选择 | 独热 | 直接当 case 选择子或 AND 使能，零译码 |
| 做加法（iid+n、assign ptr） | 二进制 | 加法器天生吃二进制 |
| 跨模块传输 | 二进制 | 7 位比 96 位省线 |
| 唤醒/写使能位图 | 独热 | 每个比较点一位（RBUS 的 preg_expand[95:0]） |

转换点的摆放原则是**"在打拍前转换"**：如 RBUS 把 7 位 preg 在 EX1 末展开成
96 位锁存（`docs/iu/08_rbus.md` §2.3），PCFIFO 在 RF 级把 pid 展开
（`docs/iu/02_bju.md` §2.7）——
从 RTL 组织意图看，这让消费阶段可以直接使用独热位；但“该拍一定时序富裕”仍是
物理实现结论，必须以综合时序而不是源码位置判断。

宽度家族对应资源：8（管线数）、32（PCFIFO/逻辑寄存器/ereg）、
64（ROB/vreg）、96（整数 preg）。

## 3. 一个小练习

读懂这两个模块后，回头看 rob.v:4334-4360 的这段：

```verilog
rob_create0_ptr <= {rob_create0_ptr[59:0], rob_create0_ptr[63:60]};  // 独热 +4
rob_create0_iid <= rob_create0_iid + 7'd4;                            // 二进制 +4
```

同一个逻辑位置同时保留二进制索引和独热选择两种表示，并按协议同步更新，是
C910 多个队列/表结构中反复出现的一种实现方法。它解释了这里的索引和选择关系，
但不能概括所有指针模块；其他模块还可能带环绕位、恢复指针或预计算 next 指针。
