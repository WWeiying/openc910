# C910 CoreMark 分支预测精细化实测报告

## 1. 测试目的与结论

本报告记录 OpenC910 RTL 在 **CoreMark 1 次迭代**上的分支预测精细化波形统计。测试的目的不是重新发布一个正式 CoreMark 分数，而是用短而完整的 CoreMark kernel，精确回答以下问题：

1. 程序实际退休了多少条件分支、Taken/Not-Taken 比例如何、架构可见误预测率是多少。
2. L0 BTB、IP 主预测、IB RAS、Addrgen 前端纠错和 BJU 后端纠错分别发生了多少次。
3. 每类 redirect 到正确目标进入 IF、进入 IDU、重新创建 ROB 项分别需要多久。
4. BJU 发现误预测后，分支退休、RTU flush、IDU/IFU 恢复各需要多久。
5. 正确预测时仍可能存在的多分支解析、RAS 晚转向等结构开销有多大。

本次结果的核心结论如下。

- CoreMark 共退休 **231,917** 条指令，其中 **47,305** 条是条件分支，占退休指令的 **20.397%**。这是一个控制流密度很高的工作负载。
- 条件分支方向预测准确率为 **93.056%**，方向误预测 **3,285** 次；加上 **7** 次 Return 目标误预测，总误预测为 **3,292** 次，即 **14.195 MPKI**。
- BJU 误预测恢复保护占 **14,103 周期，8.253%**。条件分支误预测从 BJU cancel 到 IDU/IFU 解除保护的中位数为 **3 周期**，P90 为 **6 周期**，最大为 **23 周期**。
- 条件分支误预测发生后，正确目标通常在 **1 周期**后重新进入 IF，目标指令进入 IDU 的中位数为 **3 周期**。这说明 C910 的典型路径是“前端很快重定向，后端等待退休和 RTU 恢复后再放行”。
- 多条件分支解析 stall 占 **14,544 周期，8.511%**，略高于 BJU 误预测恢复占比。它是本次 CoreMark 前端中与预测正确性不同、但同样重要的结构吞吐问题。
- 多分支 stall 与 BJU 恢复同时出现 **1,015 周期**，二者并集为 **27,632 周期，16.171%**。该并集表示“至少一种相关阻塞正在发生”，不能直接视为理想预测器可删除的周期数。
- 极少数 `cancel→目标指令进入 IDU` 出现 65、71、81 周期长尾。波形抽查表明，这些样本的 BJU 恢复保护已经在 3 至 6 周期内解除，之后是目标侧长时间没有有效指令供给。因此最大值包含目标 I-cache/取指供给等叠加效应，不是纯分支预测恢复代价。

## 3. 统计口径

### 3.1 三种不能混用的事件层级

报告使用三类口径：

| 层级 | 代表信号/数据 | 可回答的问题 | 不能回答的问题 |
|---|---|---|---|
| 架构退休口径 | RTU 退休指令、条件分支、Taken、mispred 脉冲 | 最终真正执行了多少分支，准确率和 MPKI 是多少 | 不能直接看到被冲刷的投机执行 |
| 执行级口径 | BJU EX1 有效分支及实际/预测方向 | 方向错误由 `NT→T` 还是 `T→NT` 构成 | 不能作为退休分支准确率的分母 |
| 前端事件口径 | PCGEN 选中的 L0/IP/IB/Addrgen/BJU redirect | 各转向来源的频度和后续供给延迟 | 一个 redirect 事件不等于一条退休分支 |

正式准确率必须使用架构退休口径。执行级数据包含错误路径上后来被 flush 的分支，只能用来分析机制构成。前端 redirect 只在需要改变取指流时发生，正确 Not-Taken 分支不需要 redirect，因此 redirect 总数也不能作为全部分支的分母。

### 3.2 redirect 延迟的四个端点

每个 PCGEN 已选中的分支 redirect 从发起周期开始，匹配以下端点：

| 端点 | 定义 | 解释强度 |
|---|---|---|
| `to_target_if_valid` | 正确目标 PC 首次以有效取指块进入 IF | 最直接衡量 PCGEN 是否及时转到目标 |
| `to_exact_target_idu_accept` | 目标 PC 对应的具体指令首次被 IDU 接收 | 可观察目标路径真正进入后端；本次 CoreMark 代码范围内低 15 位半字 PC 足以唯一匹配 |
| `to_first_any_idu_accept_proxy` | redirect 后任意指令首次被 IDU 接收 | 供给恢复代理；可能是 IBUF 中较老指令，不能保证就是目标指令 |
| `to_first_any_rob_create_proxy` | redirect 后任意 ROB create 首次出现 | 后端活动恢复代理；不能单独证明目标指令已经创建 |

早期 redirect 的匹配窗口会在下一次硬 redirect 处截断，以免把后续控制流事件错误归因给当前事件。因此 L0/IP 的“精确目标 IDU 已观测数”较低不表示大量预测失败，而是短时间内又发生 redirect 后不再跨事件追踪。

BJU 误预测恢复是例外：属于同一次恢复的后续 RTU flush 不会截断目标路径，因而 **3,292 个架构退休误预测均成功配对**。

### 3.3 周期统计的含义

- `mean` 是平均值，容易被少量长尾拉高。
- `median` 是中位数，表示一半事件不超过该值，更适合描述典型延迟。
- `P90` 表示 90% 的事件不超过该值。
- `max` 用于定位异常事件，但不能代替典型惩罚。
- stall 周期可以与其他 stall 或有效工作重叠，不能把各项百分比直接相加。

## 4. 架构退休结果

### 4.1 分支密度、方向分布和准确率

| 架构指标 | 事件数 | 分母 | 比例/结果 |
|---|---:|---:|---:|
| 退休指令 | 231,917 | 231,917 | 100.000% |
| 退休控制流指令 | 50,292 | 231,917 | 21.685% |
| 退休条件分支 | 47,305 | 231,917 | 20.397% |
| 实际 Taken 条件分支 | 20,449 | 47,305 | 43.228% |
| 实际 Not-Taken 条件分支 | 26,856 | 47,305 | 56.772% |
| 条件分支方向误预测 | 3,285 | 47,305 | 6.944% |
| 条件分支方向预测正确 | 44,020 | 47,305 | **93.056%** |
| 退休 Return | 239 | 239 | 100.000% |
| Return 目标误预测 | 7 | 239 | 2.929% |
| 全部分支误预测 | 3,292 | 231,917 | **14.195 MPKI** |

CoreMark 每约 4.61 条退休指令就有一条控制流指令，每约 4.90 条退休指令就有一条条件分支。即使 93.056% 的方向准确率看起来不低，较高的分支密度仍把总误预测推到 14.195 MPKI。因此该程序对分支预测器、前端转向吞吐和错误恢复都很敏感。

### 4.2 执行级方向构成

| 执行级条件分支情形 | 事件数 | 占 48,002 个执行级有效条件分支 |
|---|---:|---:|
| 预测 NT，实际 NT | 25,758 | 53.660% |
| 预测 T，实际 T | 18,930 | 39.436% |
| 预测 NT，实际 T | 1,806 | 3.762% |
| 预测 T，实际 NT | 1,508 | 3.142% |

执行级方向不一致共 **3,314** 次，其中 `NT→T` 占 54.50%，`T→NT` 占 45.50%，没有极端单边偏置。这个表适合判断错误方向构成，但不能用 `3,314 / 48,002` 替代退休准确率，因为其中包含后来可能被 flush 的投机事件。

## 5. PCGEN 转向来源

### 5.1 各级 redirect 的事件量

共识别 **43,911** 个分支相关 redirect：

| 转向来源 | 事件数 | 占全部 redirect | 微结构含义 |
|---|---:|---:|---|
| IP | 22,739 | 51.784% | 主 BTB/BHT 预测、L0 miss 后预测及 L0 早预测纠错 |
| L0 BTB | 17,061 | 38.854% | 最早的快速 Taken/Return 转向 |
| BJU | 3,309 | 7.536% | 执行级发现真实方向或目标错误后的恢复转向 |
| Addrgen | 551 | 1.255% | 前端重算直接分支/JAL 目标后纠错 |
| IB | 251 | 0.572% | 本次全部为 IB 级 RAS 转向 |

L0 BTB 与 IP 合计承担 90.638% 的 redirect，说明 CoreMark 的大多数取指流改变在前端早期解决。BJU redirect 占比只有 7.536%，但它会伴随错误路径取消、退休同步和后端恢复，单次代价明显高于 L0/IP 正确转向。

### 5.2 各类 redirect 到后续端点的延迟

以下延迟均从 redirect 被 PCGEN 选中的周期开始计数。

| 来源与子类 | 事件数 | 目标进 IF：中位/P90/最大 | 精确目标进 IDU：已观测数，中位/P90/最大 | 任意 IDU 供给：中位/P90/最大 | 任意 ROB create：中位/P90/最大 |
|---|---:|---:|---:|---:|---:|
| L0 BTB 普通转向 | 17,060 | 1 / 1 / 1 | 6,927，3 / 6 / 27 | 1 / 2 / 25 | 1 / 2 / 25 |
| L0 RAS 快速转向 | 1 | 1 / 1 / 1 | 0，未观测 | 2 / 2 / 2 | 2 / 2 / 2 |
| IP 主预测 | 19,629 | 1 / 1 / 1 | 10,170，3 / 4 / 33 | 1 / 1 / 20 | 1 / 2 / 20 |
| IP：L0 miss 后预测 | 2,354 | 1 / 1 / 1 | 1,075，3 / 3 / 14 | 1 / 1 / 11 | 1 / 4 / 13 |
| IP：纠正 L0 mistaken | 545 | 1 / 1 / 1 | 60，3 / 4 / 8 | 1 / 1 / 3 | 1 / 2 / 4 |
| IP：纠正 L0 Taken/Target | 211 | 1 / 1 / 1 | 102，3 / 3 / 20 | 1 / 1 / 16 | 1 / 2 / 17 |
| IB RAS | 251 | 1 / 1 / 1 | 47，6 / 7 / 33 | 1 / 2 / 3 | 1 / 2 / 3 |
| Addrgen 直接目标纠错 | 551 | 1 / 1 / 34 | 241，3 / 5 / 47 | 3 / 3 / 47 | 1 / 2 / 7 |
| BJU 条件方向误预测 | 3,302 | 1 / 1 / 42 | 3,287，3 / 3 / 81 | 3 / 3 / 81 | 6 / 9 / 84 |
| BJU Return 目标误预测 | 7 | 1 / 1 / 1 | 7，3 / 12 / 12 | 3 / 12 / 12 | 14 / 15 / 15 |

这个表揭示了三个不同层面的事实。

第一，绝大多数 redirect 在下一周期就能让正确目标进入 IF。L0、IP、IB 和典型 BJU 的 `目标进 IF` 中位数均为 1 周期，表明 PCGEN 选中转向后本身没有长组合延迟。

第二，正确目标进入 IF 不等于目标指令已经进入后端。L0/IP 精确目标进入 IDU 的典型值约为 3 周期；IB RAS 的精确目标中位数为 6 周期；BJU 条件误预测的典型值也是 3 周期，但会同时受后端恢复状态约束。

第三，`任意 IDU/ROB` 是供给恢复代理，不一定是目标指令。比如 IB RAS 后任意 IDU 供给中位数为 1 周期，而精确目标是 6 周期，这表示缓冲区内可能仍有较老或同一取指块中的其他指令在流动，不能把前者解释成 Return 目标已经到达。

### 5.3 L0 早预测被 IP 纠正

通过“IP mistaken 事件向前匹配最近 L0 redirect，并要求 L0 lookup PC 与 IP VPC 完全一致”，得到 **545 对** L0→IP 纠正事件，身份匹配率为 100%。

| L0 到 IP 纠正延迟 | 事件数 | 比例 |
|---|---:|---:|
| 1 周期 | 307 | 56.330% |
| 2 周期 | 229 | 42.018% |
| 3 周期 | 9 | 1.651% |
| 合计 | 545 | 100.000% |

平均延迟为 **1.453 周期**，中位数 1，P90 为 2，最大 3。这类事件是前端小纠错：L0 用更早但信息较少的预测换取低延迟，IP 随后用更完整的信息校验。它会浪费少量错误路径取指，但与 BJU 级误预测的全核投机恢复不是同一级代价。

## 6. 分支预测组件事件

| 组件事件 | 次数 | 解释 |
|---|---:|---|
| L0 hit，按 RTL 接受条件门控 | 11,309 | L0 预测信息在对应有效条件下命中 |
| L0 miss，按 RTL 接受条件门控 | 2,852 | L0 未提供可用预测，需要后续级处理 |
| L0 mispred，按 RTL 接受条件门控 | 610 | 后续级认为 L0 的方向、类型或目标需要纠正 |
| Indirect BTB 检查 | 0 | 本次 ROI 没有进入该统计路径 |
| Indirect BTB miss | 0 | 因检查数为 0，不能评价间接 BTB 能力 |
| RAS redirect | 647 | 所有被观测的 RAS 转向，包括不同前端路径 |
| RAS 类型纠正 | 0 | 本次未观察到该类纠正 |

`l0_hit_gated`、`l0_miss_gated` 和 `l0_mispred_gated` 是 RTL 不同逻辑条件下的门控事件，不保证互斥，也不保证三者之和就是统一的 L0 access 分母。因此本报告不把 `11,309 / (11,309 + 2,852)` 写成标准 L0 命中率，也不把 `610` 简单除以上述和作为 L0 误预测率。若要发布 L0 命中率，需要新增同一接受点、同一请求身份下互斥完备的 access/hit/miss 计数。

## 7. BJU 误预测恢复链

### 7.1 架构误预测的完整恢复时延

下表只使用成功匹配到 RTU 架构退休误预测的事件，排除了最终未退休的投机错误。

| 误预测类型 | 事件数 | 延迟区间 | 平均 | 中位 | P90 | 最大 |
|---|---:|---|---:|---:|---:|---:|
| 条件方向错误 | 3,285 | cancel→目标 IF | 1.063 | 1 | 1 | 42 |
| 条件方向错误 | 3,285 | cancel→精确目标 IDU 接收 | 3.631 | 3 | 3 | 81 |
| 条件方向错误 | 3,285 | cancel→误预测分支退休 | 2.251 | 1 | 4 | 21 |
| 条件方向错误 | 3,285 | 分支退休→RTU flush | 1.000 | 1 | 1 | 2 |
| 条件方向错误 | 3,285 | cancel→RTU flush | 3.251 | 2 | 5 | 22 |
| 条件方向错误 | 3,285 | cancel→IDU 恢复放行 | 4.251 | 3 | 6 | 23 |
| 条件方向错误 | 3,285 | cancel→IFU 保护解除 | 4.251 | 3 | 6 | 23 |
| Return 目标错误 | 7 | cancel→目标 IF | 1.000 | 1 | 1 | 1 |
| Return 目标错误 | 7 | cancel→精确目标 IDU 接收 | 5.571 | 3 | 12 | 12 |
| Return 目标错误 | 7 | cancel→误预测分支退休 | 9.143 | 10 | 10 | 10 |
| Return 目标错误 | 7 | 分支退休→RTU flush | 1.000 | 1 | 1 | 1 |
| Return 目标错误 | 7 | cancel→RTU flush | 10.143 | 11 | 11 | 11 |
| Return 目标错误 | 7 | cancel→IDU/IFU 恢复 | 11.143 | 12 | 12 | 12 |

典型条件方向误预测的恢复链可概括为：

```text
BJU EX2 cancel / PCGEN redirect
    ├─ 约 1 周期：正确目标重新进入 IF
    ├─ 中位 1 周期：误预测分支到达退休点
    ├─ 再 1 周期：RTU 发出 flush
    └─ 中位 3 周期：IDU/IFU 解除误预测保护
```

这不是说“完整误预测代价只有 3 周期”。BJU cancel 已经发生在分支经过 IF、IP、IB、ID、IR、IS、RF 和 BJU 执行之后；在 cancel 之前，错误路径已经占用了前端与后端资源。此表量的是 **BJU 已确认错误之后的恢复链**，不包含分支从取指到执行发现错误之前的时间，也不等价于 IPC 损失。

Return 目标误预测只有 7 个样本，不能据此稳定估计总体分布；但它们一致显示分支退休明显更晚，cancel 到恢复中位数达到 12 周期。这符合“Return/JALR 目标错误发现后，仍需等待该分支及更老指令满足退休恢复条件”的机制。

### 7.2 条件方向误预测的长尾

| 恢复区间 | P95 | P99 | 超过 3 周期 | 超过 6 周期 | 超过 10 周期 |
|---|---:|---:|---:|---:|---:|
| cancel→目标 IF | 1 | 1 | 10 | 7 | 7 |
| cancel→精确目标 IDU 接收 | 4 | 33 | 220 | 60 | 48 |
| cancel→误预测分支退休 | 7 | 16 | 685 | 199 | 95 |
| cancel→RTU flush | 8 | 17 | 904 | 244 | 96 |
| cancel→IDU/IFU 恢复 | 9 | 18 | 993 | 296 | 105 |

`cancel→精确目标 IDU` 的 P99 突然达到 33 周期，说明尾部受到预测器之外的目标侧供给条件影响。三个最大样本的静态波形抽查结果是：

| cancel 周期 | 目标进 IF | IDU/IFU 恢复 | 精确目标进 IDU | 观察 |
|---:|---:|---:|---:|---|
| 37,385 | 42 | 6 | 81 | 正确目标地址长期停留，直到约 81 周期后才出现有效 IDU 指令 |
| 40,907 | 1 | 3 | 65 | 恢复已完成，但目标侧长时间无有效 IDU 供给 |
| 145,409 | 1 | 3 | 71 | 恢复已完成，目标 IF 地址随后长时间停滞，目标指令在第 71 周期进入 IDU |

因此分析误预测器时应优先看中位数和 P90；分析系统最坏情况时，再把最大值与 I-cache refill、iTLB、取指重发和目标地址热点联合检查。

### 7.3 事件数闭环

| BJU 事件分类 | 数量 |
|---|---:|
| EX2 BJU cancel 总数 | 3,318 |
| 同周期被更高优先级 PCGEN 来源遮蔽、未选中 BJU redirect | 9 |
| PCGEN 实际选中的 BJU redirect | 3,309 |
| 最终架构退休的条件方向误预测 | 3,285 |
| 最终架构退休的 Return 目标误预测 | 7 |
| 已选中但后来没有作为架构误预测退休的投机/重叠事件 | 17 |

满足：

```text
3318 = 9 + 3309
3309 = 3285 + 7 + 17
```

同时，BJU EX1 到 EX2 的 IID/PID 身份匹配失败为 **0**，架构退休误预测成功配对 **3,292 / 3,292**。这两个闭环是本次细粒度延迟统计可信度的关键校验。

## 9. 如何解释“预测正确仍有开销”

正确预测不是统一的零开销事件，应按目标产生位置区分：

| 正确情形 | 本次可观察证据 | 解释 |
|---|---|---|
| 正确 Not-Taken | 不产生 redirect，执行级有 25,758 次 | 顺序 PC 已在取指，通常没有控制流转向气泡，但分支仍占 BJU/队列资源 |
| L0 正确 Taken | L0 redirect 的目标通常 1 周期进入 IF | 最早转向路径；目标进入 IDU 仍需经过后续前端级 |
| IP 正确 Taken | IP 主预测 19,629 次，目标通常 1 周期进入 IF | 比 L0 更晚获得预测信息，可能形成较小的前端间隙 |
| IB RAS 正确 Return | 251 次，精确目标进入 IDU 中位 6 周期 | Return 在更晚级产生目标，且前端缓冲中的任意供给不能代表 Return 目标已经到达 |
| 同一取指块有多个条件分支 | 14,544 stall 周期 | 即使每条分支方向都预测正确，前端解析吞吐限制仍会产生等待 |

本次 FSDB 可以精确测量 redirect 发起后的目标传播与供给恢复，但没有给每条“正确预测分支”建立从该分支最初进入 IF 到目标进入 IDU 的全生命周期身份链。因此不能仅凭本表宣布“L0 正确 Taken 固定 0 bubble”或“IP 正确 Taken固定 1 bubble”。要得到这种严格逐分支惩罚，还需在 IF 入口给 fetch block/branch 分配可跨 IF、IP、IB、IDU、ROB 和 BJU 保持的身份标签。

## 10. 性能瓶颈判断

本次数据支持以下优先级。

### 10.1 第一优先级：条件分支方向准确率与误预测恢复

条件分支占退休指令 20.397%，方向误预测率 6.944%，总误预测 14.195 MPKI。每个架构误预测不仅触发 BJU redirect，还使 IDU/IFU 恢复保护典型持续 3 周期、P90 持续 6 周期，并浪费发现错误前已经进入流水线的错误路径工作。因此降低方向误预测仍有较高价值。

不过，不能用 `14,103 / 170,876 = 8.253%` 直接宣称理想预测器会提升 8.253%。这些周期可能与其他阻塞重叠，部分周期前端或其他单元仍有有效活动；预测器改变也会改变 cache、队列和指令时序。精确性能收益必须通过 RTL A/B 实验测量。

### 10.2 同等重要：多分支取指块处理吞吐

多分支 stall 为 14,544 周期，略高于 BJU 恢复 stall，而且 12,070 个连续片段的中位数为 1 周期。这说明问题不是少量灾难性长停顿，而是高频、短促的前端吞吐损失。应重点研究：

- IP 对同一 fetch block 多个条件分支为何需要分拍处理；
- 能否并行完成更多分支位置、方向和目标选择；
- PCFIFO/预测上下文是否支持更高的每周期分支处理能力；
- 增强后是否引入新的关键路径、面积或错误优先级问题。

### 10.3 Return 路径样本少，但单次恢复更长

239 次退休 Return 中有 7 次目标误预测。样本数很小，但它们的 cancel→恢复中位数为 12 周期，明显长于条件方向错误的 3 周期。后续可用专门的深调用、非规则返回和 RAS 溢出测试，分开验证 RAS 容量、push/pop 时机、L0 RAS 快路径和异常恢复一致性。

### 10.4 本次不能评价 Indirect BTB

本次 `indirect_btb_checks=0`，因此 CoreMark 这一 ROI 不能说明间接分支预测器好坏。不能把 0 miss 解释成 100% 命中。应使用函数指针、虚调用、解释器 dispatch 或专门 JALR target pattern benchmark 补足。

### 11.2 必须保留的限制

1. 本次只有 1 次 CoreMark 迭代，适合波形机制研究，不适合正式分数稳定性评估。
2. IFU→IDU 精确目标 PC 使用低 15 位半字地址匹配。本次 CoreMark 代码地址范围允许唯一匹配；更大程序需要重建高位或导出完整 PC。
3. L0 组件事件来自不同 RTL 门控条件，不能直接构造统一命中率。
4. `任意 IDU accept` 和 `任意 ROB create` 是供给代理，不是目标指令身份匹配。
5. `目标进入 IF/IDU` 的最大长尾可能叠加 I-cache、iTLB、重发、前端缓冲和后续 redirect，不能全算到预测器。
6. stall 周期允许重叠，且 stall 存在时其他独立指令仍可能执行或退休，不能直接转换为可删除周期。
7. 精确的“理想零延迟、100% 准确预测器收益”仍需要可运行的 RTL 对照实验；仅靠现有计数器只能给出结构性上界和归因线索。
