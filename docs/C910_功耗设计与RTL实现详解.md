# C910 功耗设计与 RTL 实现详解

## 1. 本文要回答什么，以及 RTL 能证明到什么程度

处理器的低功耗设计不是在功能完成之后再加入几个“关时钟”信号，而是从流水线组织、存储阵列划分、乱序资源管理、空闲状态协议一直延伸到综合和物理实现的一组系统性取舍。本文以本仓库中的 C910 RTL 为主要证据，解释这些取舍怎样降低无效翻转、缩小一次操作真正激活的电路范围，并在不破坏乱序状态、存储一致性和调试唤醒能力的前提下让核心进入低功耗状态。叙述顺序从 CMOS 电路为什么耗电开始，随后落到 C910 的全局时钟、模块时钟、阵列使能、表项级门控以及实现侧电源意图，目的是把“某个信号怎么写”与“它为什么有功耗价值”连接起来。

必须先划清证据边界。RTL 可以明确证明设计是否表达了时钟门控条件、哪些存储体会被访问、低功耗状态进入前等待哪些队列排空，以及某个计算单元被怎样流水化或复用；RTL 本身不能给出最终芯片的毫瓦数，也不能证明某项技术在版图后一定节省了多少能量。后者还依赖标准单元和 SRAM 宏的功耗模型、门控时钟树的实际负载、布线寄生、电压温度工艺角、工作负载活动率以及布局布线结果。因此，本文把结论分成三个层次：直接引用信号和状态机的是 **RTL 事实**；由电路原理推导出的收益和代价是 **工程解释**；需要 SAIF、门级网表、STA、功耗分析或硅后测量才能确认的内容会明确写成 **待实现数据验证的判断**。这种区分很重要，因为一份没有真实活动率的综合功耗报告，即使小数点后有很多位，也可能比基于 RTL 的定性判断更容易误导。

还要区分“源码中保留了接口或状态名”和“当前公开生成配置真正实现了对应数据通路”。例如，当前 [`ct_idu_rf_prf_fregfile.v`](../C910_RTL_FACTORY/gen_rtl/idu/rtl/ct_idu_rf_prf_fregfile.v) 实现了一组 64×64 bit 的浮点物理寄存器存储，而在 [`ct_idu_top.v`](../C910_RTL_FACTORY/gen_rtl/idu/rtl/ct_idu_top.v) 中另行例化的两个 [`ct_idu_rf_prf_vregfile.v`](../C910_RTL_FACTORY/gen_rtl/idu/rtl/ct_idu_rf_prf_vregfile.v) 包装，其寄存器实例被注释、读输出固定为零。类似地，D-cache 和 L2 仍可见 ECC 接口、状态和信号名，但当前生成 RTL 的若干 ECC 编解码与修复路径被注释或常量关闭。本文只把实际生效的逻辑计入当前配置的功耗机理；若要推断商业芯片、另一套生成参数或完整向量/ECC 配置，必须取得与该配置一致的 RTL、宏和网表重新分析。

为便于沿源码阅读，本文保留 RTL 中常用的英文缩写，但在这里统一说明其职责。IFU 是取指单元，IDU 负责译码、重命名和发射，LSU 是访存单元，BIU 是核心总线接口，MMU 负责地址翻译；ROB 是重排序缓冲区，PRF 是物理寄存器文件，PST 是跟踪物理寄存器生命周期的状态表。ICG 指集成时钟门控，CEN 指 SRAM 的访问使能；way 是组相联 cache 的一路，bank 是可相对独立激活的阵列分块。后文中的 create、issue、write-back、retire、stall 和 flush 分别对应创建、发射、写回、退休、停顿和清空。保留英文信号词是为了能直接回到 RTL 搜索，并不表示这些词代表相互独立的硬件级。

## 2. 从半导体物理理解处理器为什么耗电

在 CMOS 逻辑中，最容易由微结构直接控制的是动态功耗。一个逻辑节点从 0 变为 1 时，电源给该节点及其连线的等效电容充电；节点从 1 变为 0 时，电容中储存的能量又在下拉网络中耗散。对大量节点求和后，常用近似式为

```text
P_dynamic ≈ α · C_eff · V_DD² · f
```

其中，`α` 是一个时钟周期内发生有效充放电的平均活动因子，`C_eff` 是被驱动门输入、扩散结和金属连线形成的等效电容，`V_DD` 是供电电压，`f` 是频率。这个公式解释了处理器 RTL 中三类最常见的低功耗动作。时钟门控主要降低 `α`，因为门控后的触发器时钟端及其下游数据逻辑不再随周期翻转；存储体分 bank、按 way 选择和按字段更新同时降低 `α` 与本次事件看到的 `C_eff`；电压调节通过平方项起作用，潜在收益最大，但本仓库的核心 RTL 没有提供可据此宣称完整 DVFS 控制器的证据。频率降低会近似降低单位时间动态功耗，却不必然降低完成同一任务的总能量，因为运行时间可能同步增长。

真实芯片还存在短路功耗和静态功耗。输入翻转期间，PMOS 与 NMOS 可能短暂同时导通，形成从电源到地的短路电流；输入边沿越慢，这段重叠导通通常越显著。即使逻辑完全不翻转，亚阈值泄漏、栅隧穿、结漏电以及 SRAM 单元的保持电流仍然存在。工艺尺寸缩小、温度升高或采用较低阈值电压单元，往往会放大泄漏。于是，“停时钟”主要消除动态翻转，却不能像切断电源那样消除该电源域的大部分泄漏；“切断电源”又要求隔离、状态保存和恢复，并引入较长的进出延迟。C910 核心 RTL 中可直接确认的是精细时钟门控和低功耗停钟协议，而仓库中的电源开关、隔离和保持方案出现在示例 UPF 与示例 PMU 中，不能不加区分地当作核心内部已经实现的功能。

阈值电压为什么同时牵动功耗与速度，可以从亚阈值区理解。当栅压低于 `V_th` 时，晶体管并非理想关断，沟道电流会随 `(V_GS - V_th)` 近似呈指数变化；降低 `V_th` 能让导通电流更早建立、逻辑门更快，却会显著增加关断泄漏。温度升高又会提高亚阈值泄漏，因此一个常温下可接受的空闲功耗，在高温角可能明显恶化。多阈值单元方法正是利用这一矛盾：只在关键路径上使用较快但较漏的 LVT，非关键路径尽量使用 HVT；选择比例必须由 STA 和 leakage 分析共同决定，不能从 RTL 模块名直接推断。

SRAM 的能量来源也与普通触发器阵列不同。一次读通常要预充较长的 bitline，选通 wordline 后由很小的单元电流制造差分，再由 sense amplifier 放大；一次写则要用写驱动器压过存储单元原有状态。即使最终只取 16 字节，若组织不当也可能预充和摆动远大于 16 字节的列线。因而 cache 分 bank、way prediction、CEN 和字节写掩码不仅是逻辑上的“少处理一些位”，它们真正要达到的物理效果是少激活 wordline、少预充 bitline、少开启 sense amplifier。是否确实做到这一点还取决于 SRAM 宏端口定义和内部组织，必须结合 memory compiler 的功耗表确认。

时钟网络尤其值得单独理解。普通数据节点只在数据改变时翻转，时钟却在工作期间每周期翻转两次，并驱动大量触发器时钟端和缓冲树。它同时具有接近 1 的活动因子、很大的总电容和严格的偏斜要求，因而常是动态功耗的重要来源。另一方面，插入门控单元并非免费：门控单元本身有输入电容和内部功耗，门控使能要满足时序，时钟树综合还必须为门控后的分支控制偏斜。只有当下游负载足够大、空闲时间足够长时，省下的时钟树和触发器翻转能量才会超过门控开销。C910 既有粗粒度核心停钟，也有模块级、表项级和字段级门控，正是在不同空闲粒度上寻找这一收支平衡。

功耗还必须用“完成有用工作所需能量”来衡量，而不能只看瞬时瓦数。若一次分支误预测让前端、译码、重命名和执行路径上的错误指令翻转数十个周期，预测器本身多消耗少量能量却可能减少整个核心的浪费；若预取器把本来会停顿很久的数据提前带入缓存，它可能以更多访存换取更短运行时间。反过来，错误预取既占总线和 cache 容量，又增加阵列与互连活动。评价公式因此应同时保留 `P_average`、总能量 `E = ∫Pdt`、每退休指令能量和完成固定工作负载的能量，而不是只追求某一个模块的最低局部功耗。

## 3. C910 的分层门控不是一个开关，而是一套活动范围控制

C910 大量模块通过统一的 [`gated_clk_cell.v`](../C910_RTL_FACTORY/gen_rtl/clk/rtl/gated_clk_cell.v) 表达门控意图。其有效条件为

```verilog
(global_en && (module_en || local_en)) || external_en
```

这四类使能承担不同层次的职责。`global_en` 是上层是否允许该门控分支工作的总条件；`module_en` 通常来自模块级 ICG 配置，它与 `local_en` 做“或”，所以置 1 的准确含义是**在全局使能允许时强制该模块的局部门控分支开钟**，而不是关闭模块；`local_en` 是由当前流水事件产生的精细使能，例如“本周期有新表项写入”或“某一级有有效指令”；`external_en` 则允许某些外部维护或唤醒事件绕过常规局部条件。`pad_yy_icg_scan_en` 接到集成门控单元的测试使能端，使扫描测试时能够强制传播时钟。这里体现的是一个重要的可测性原则：功能模式下越激进的时钟门控，越需要在 DFT 模式下提供可控旁路，否则扫描链中的触发器会因收不到时钟而无法移位。

这种模块级强制开钟并不是抽象推测，而是有明确的软件控制落点。[`ct_cp0_regs.v`](../C910_RTL_FACTORY/gen_rtl/cp0/rtl/ct_cp0_regs.v) 的 `MHINT2[22:14]` 写入 `local_icg_en[8:0]`，复位值为全零；`[0]` 到 `[7]` 依次送往 IFU、IDU、IU、LSU、MMU、BIU、RTU 和 VFPU，其中 IU 位还共享给 CP0 regs/HPCP，MMU 位也共享给 PMP；`[8]` 形成 `cp0_xx_core_icg_en`，直接并入全局 `core_clk_en`。默认全零时，各局部门控由事件型 `local_en` 决定；把某位写成 1，会绕过相应模块内部的局部空闲判断，便于调试门控遗漏、比较门控开关前后的波形或定位门控时序问题，但通常会增加动态功耗。尤其 core 位不是“打开一种节能模式”，而是强制主核心时钟保持可用。做功耗 A/B 实验时必须记录这九位，否则两个看似相同的程序可能只是因为门控强制状态不同而得到不同结果。

该封装的实现边界必须准确理解。定义 `C910_USE_TSMC28_ICG` 时，它实例化工艺相关的 `CKLNQD4BWP12T40P140` 集成时钟门控单元；未定义该宏时，代码直接执行 `assign clk_out = clk_in`。因此，普通 RTL 仿真中的门控时钟可能保持透明，局部门控条件仍可作为设计意图和性能观察信号，但不能据波形中“时钟没有停”就认定 ASIC 实现没有门控。后端文件 [`ct_top_dc.f`](../backend/flist/ct_top_dc.f) 为 ASIC 综合定义了 TSMC SRAM 与 ICG 宏，使综合看到的硬件与通用仿真模型不同。反过来，也不能仅凭 RTL 中出现 `gated_clk_cell` 就宣称已经得到某个功耗收益；还要确认宏映射、门控检查、CTS、活动率和后端报告。

对当前源码做文字级统计，可以找到 748 处 `gated_clk_cell` 实例，分布于 240 个 Verilog 文件，IFU、IDU、LSU 和 CIU 等大模块中尤其密集。这个数字只说明源代码把门控意图铺到了许多局部状态和数据通路，既不是综合后的 ICG 数量，也不是门控效率。综合可能合并、复制或优化门控结构，宏定义与层次展开也会改变最终数量。仓库现有 [`clock_gating.rpt`](../backend/syn/ct_top/v1-dc/reports/clock_gating.rpt) 显示 0 个门控单元，但报告同时明确警告“尚未执行门控单元识别，已有门控不会被报告”；所以该 0 不能反证 RTL 门控不存在。这正是阅读 EDA 报告时必须先看 warning、分析模式和识别步骤，而不能只摘最终数字的例子。

精细门控最有价值的地方不是让一个完整模块偶尔关闭，而是让未被此次操作触及的状态保持静止。以 AIQ 表项、ROB 表项和物理寄存器状态为例，C910 经常把“表项有效位”“创建数据”“某个源操作数 ready 位”“PCFIFO 附加信息”等字段放在不同的门控时钟下。这样，一个执行结果广播只需要唤醒命中的源状态，不必让队列中所有字段同时翻转；创建一个不带某类附加信息的操作时，也不必时钟整个宽表项。代价是门控条件更多、使能扇出和时钟树分支更复杂，并且每个使能都要经过门控建立时间检查。由此可见，功耗优化与时序优化并不是彼此独立的两项工作：字段切得越细，数据电容越小，但控制和门控网络越可能成为新的时序与布线压力。

## 4. 从 WFI 到真正停钟：先排空，再关闭，再保留唤醒通道

一个乱序核心不能在看到 WFI 后立即把时钟掐断。此时前端可能仍有取指或 refill，LSU 中可能有尚未写出的 store，BIU 上可能存在未完成的读写事务，MMU 也可能正在做 uTLB refill。若直接停钟，外部系统可能永远等不到响应，store 的体系结构可见性也可能不完整。C910 在 [`ct_cp0_lpmd.v`](../C910_RTL_FACTORY/gen_rtl/cp0/rtl/ct_cp0_lpmd.v) 中用 `IDLE → WAIT → LPMD` 状态机处理这件事：收到 WFI 后先进入 WAIT，向 IFU、LSU 和 MMU 发出 no-op 请求；只有 IFU、LSU、BIU 和 MMU 都返回 no-op 确认，状态机才进入 LPMD，并通过 `cp0_yy_clk_en` 关闭正常核心时钟。这里的“no-op”不是说模块从此没有功能，而是说其内部已达到没有待完成微结构事务、可以安全冻结的静止点。

各模块对“静止”的定义与其职责一致。[`ct_ifu_ifctrl.v`](../C910_RTL_FACTORY/gen_rtl/ifu/rtl/ct_ifu_ifctrl.v) 要求 refill 和 IPB 预取活动停止，并阻止新 fetch 进入；[`ct_lsu_ctrl.v`](../C910_RTL_FACTORY/gen_rtl/lsu/rtl/ct_lsu_ctrl.v) 要求 WMB、SQ、RB、LFB、VMB 和 VB 等结构为空；[`ct_biu_lowpower.v`](../C910_RTL_FACTORY/gen_rtl/biu/rtl/ct_biu_lowpower.v) 分别观察读写通道 busy 状态；[`ct_mmu_arb.v`](../C910_RTL_FACTORY/gen_rtl/mmu/rtl/ct_mmu_arb.v) 则确认没有正在进行的 uTLB refill。它们合在一起形成一个分布式静默协议。体系结构上，这一协议保护了精确状态与内存顺序；电路上，它把停钟前的一次性排空开销换成之后长时间不翻转的收益。因此，WFI 很短或频繁被打断时不一定节能，空闲区间足够长时收益才显著。

全局时钟控制位于 [`ct_clk_top.v`](../C910_RTL_FACTORY/gen_rtl/clk/rtl/ct_clk_top.v)。`core_clk_en` 并非只由 CP0 的正常工作位控制，它还汇合中断唤醒、调试唤醒、snoop 有效、HAD、PMP 访问等条件。这意味着进入低功耗状态后，核心主时钟可以停止，但足以发现外部事件的逻辑仍必须活着。[`ct_biu_other_io_sync.v`](../C910_RTL_FACTORY/gen_rtl/biu/rtl/ct_biu_other_io_sync.v) 对调试请求使用同步触发器并形成唤醒条件；[`ct_biu_lowpower.v`](../C910_RTL_FACTORY/gen_rtl/biu/rtl/ct_biu_lowpower.v) 的 snoop AC 通道使用 `forever_coreclk`，使一致性请求不会因为正常核心时钟停止而永久丢失。这里可把时钟域理解成“睡眠主体”和“门卫”：主体可以冻结，门卫必须在一个持续时钟域中监听中断、调试和一致性事件，再安全地重新打开主体时钟。

这套 RTL 主要实现的是时钟停止而非核心电源切断。时钟停止后，普通触发器自然保持状态，不需要把 ROB、PST 或 CSR 复制到 retention cell；同时，标准单元和 SRAM 的泄漏仍然存在。若系统要进一步进入 power-off 状态，就必须在核外或实现层定义电源开关、隔离、保持和复位语义。不能把这两层混为一谈，否则会误认为 `cpu_in_lpmd` 等价于供电已经关闭。

## 5. IFU：每周期工作路径上的能量必须按访问范围精打细算

前端是功耗设计最敏感的区域之一，因为正常运行时它几乎每周期都尝试预测、取指和组织指令。C910 当前配置的 L1 I-cache 为 64 KiB、2 路组相联，cache line 为 64 字节，正常一次取指数据窗口为 128 bit，也就是 16 字节。内部 PC 总线省略了架构字节地址的 bit 0，所以读 RTL 位号时必须先恢复这一编码关系。这个细节直接影响功耗分析：不能把内部 `pc[4:3]` 的四种取值误读成 8 字节行内位置，它对应的是 64 字节行内的四个 16 字节取指块。

[`ct_ifu_icache_data_array0.v`](../C910_RTL_FACTORY/gen_rtl/ifu/rtl/ct_ifu_icache_data_array0.v) 和对应的 way1 数据阵列把每一路组织为四个 32 bit bank，每个 bank 有自己的门控时钟，四个 bank 组合成一次 128 bit 输出。[`ct_ifu_icache_if.v`](../C910_RTL_FACTORY/gen_rtl/ifu/rtl/ct_ifu_icache_if.v) 又分别为两个 way、各数据 bank 和预译码阵列生成 CEN 与时钟使能。正常顺序取指时，为得到完整 128 bit 块，会读取预测 way 的四个 32 bit bank；它不是“每次只读一个 32 bit bank”。发生 change-flow 且目标落在取指块中部时，控制逻辑可以屏蔽目标之前无用的 bank，从而避免读取随后一定会被丢弃的数据。这个例子说明，准确的功耗解释必须跟着数据宽度和有效字节走，不能只看到“banked”就笼统地断言一次只激活一个 bank。

way prediction 进一步限制活动范围。[`ct_ifu_pcgen.v`](../C910_RTL_FACTORY/gen_rtl/ifu/rtl/ct_ifu_pcgen.v) 在预测有效时只选择相应 way；预测被关闭时则显式读取两路。读取单路可减少一半相关数据阵列的本次访问电容，但错误 way 预测会带来重取和停顿，所以实际能量收益取决于命中准确率。tag 侧也没有机械地在每个顺序 16 字节块都重复读取：顺序流中，新的 64 字节 line 起始位置才触发正常 tag 访问，而同一 line 内后续块可以复用已经建立的命中与 way 信息。于是，C910 的 I-cache 能量策略可以概括为：先利用空间连续性减少 tag 访问频率，再用 way prediction 限制数据路数，最后按 change-flow 的有效字节范围屏蔽无用 bank。三层优化分别作用于访问次数、路数和字节范围。

分支预测器本身也是一个有层次的高活动存储系统，而不只是一块抽象的“预测逻辑”。[`ct_ifu_l0_btb.v`](../C910_RTL_FACTORY/gen_rtl/ifu/rtl/ct_ifu_l0_btb.v) 的 16 个寄存器表项会并行比较 tag，容量很小、目标取得较早，但每次有效查询仍会活动一组相联比较器和目标选择网络；主 [`ct_ifu_btb.v`](../C910_RTL_FACTORY/gen_rtl/ifu/rtl/ct_ifu_btb.v) 在当前配置中用两块 512×22 tag SRAM 和两块 512×44 data SRAM 形成 512 行×4 个固定位置槽，容量更大，正常未停顿取指时会按使能访问同步 SRAM。[`ct_ifu_bht_pre_array.v`](../C910_RTL_FACTORY/gen_rtl/ifu/rtl/ct_ifu_bht_pre_array.v) 的 1024×64 predict SRAM 与 [`ct_ifu_bht_sel_array.v`](../C910_RTL_FACTORY/gen_rtl/ifu/rtl/ct_ifu_bht_sel_array.v) 的 128×16 select SRAM 负责条件分支方向。这个组织把热点目标、较大目标容量和方向历史分到不同阵列，避免用一张同时做所有事情的超大相联表；代价是这些结构在前端活跃时会持续消耗读能量，而且错误预测会让 I-cache、译码、重命名、队列和执行单元继续处理最终被丢弃的错误路径。因而，预测器价值不能只用其局部毫瓦衡量，还要计算它减少了多少错误路径周期和全流水无效活动。

预测状态必须在“最新”与“可恢复”之间复制，这也有明确能量成本。[`ct_ifu_bht.v`](../C910_RTL_FACTORY/gen_rtl/ifu/rtl/ct_ifu_bht.v) 同时保存 22 bit 投机历史 `vghr_reg` 和 22 bit 退休历史 `rtughr_reg`，前者随预测推进，RTU flush 时由后者恢复；[`ct_ifu_ras.v`](../C910_RTL_FACTORY/gen_rtl/ifu/rtl/ct_ifu_ras.v) 则维护 12 项前端投机返回栈和 6 项退休侧恢复副本。双份或部分复制的状态增加寄存器、局部门控和恢复写入能量，却让预测器不必停下来等待分支退休。误预测的真实能量代价因此至少包括三部分：预测器状态回滚、错误路径已发生的阵列/队列/执行活动，以及重新取正确路径的访问。评价改进时应同时统计 L0/主 BTB、BHT、RAS 的查询与更新次数，误预测类型、错误路径指令数、恢复周期和固定任务总能量；只看预测器自身的访问功耗会系统性低估准确率带来的全核收益。

分支预测器同样避免无效更新。[`ct_ifu_bht.v`](../C910_RTL_FACTORY/gen_rtl/ifu/rtl/ct_ifu_bht.v) 带有写缓冲，并在饱和计数器已经处于相同方向、更新不会改变状态时抑制实际阵列写入。对 SRAM 或寄存器阵列而言，写入通常意味着字线、位线、写驱动和局部时钟都活动；“结果与原值相同”在功能上无害，却仍可能消耗一次完整写能量。先在小写缓冲和控制逻辑中判断是否真的改变状态，是用少量比较逻辑换取减少大阵列写活动。这个优化对高频循环分支尤其有意义，因为强 taken 或强 not-taken 计数器会长期饱和。

[`ct_ifu_lbuf.v`](../C910_RTL_FACTORY/gen_rtl/ifu/rtl/ct_ifu_lbuf.v) 展示了另一种体系结构级节能思路：检测符合条件的短循环后，在本地 loop buffer 中重放指令，减少重复访问更大、更远的前端存储结构。它并不是把整个 IFU 完全关闭，BHT 更新和必要的控制仍然存在，而且 entry 自身也使用表项有效与创建数据门控。因此，loop buffer 的价值应理解为缩短频繁循环的“数据搬运半径”，而不是简单的零功耗模式。局部小存储每次访问电容较小，若命中率和循环覆盖率足够高，既能减轻 I-cache/预译码阵列活动，也能降低前端路径延迟；若循环很少或不满足捕获条件，则这部分硬件自身仍有面积与泄漏成本。

前端与后端之间的弹性缓冲也会显著改变活动范围。[`ct_ifu_ibuf.v`](../C910_RTL_FACTORY/gen_rtl/ifu/rtl/ct_ifu_ibuf.v) 用 32 个 half-word entry 吸收 16 字节取指窗口与三条译码宽度之间的速率差，每个 [`ct_ifu_ibuf_entry.v`](../C910_RTL_FACTORY/gen_rtl/ifu/rtl/ct_ifu_ibuf_entry.v) 又把 valid、指令/异常 payload 和 PC 更新放在不同门控时钟下。没有更老数据时，bypass 可把本拍 half-word 直接拼成指令送给 IDU，减少一次 entry 写入和随后读出；当后端不能接收时，数据才需要驻留或继续反压。与之并行的 32 项 [`ct_iu_bju_pcfifo.v`](../C910_RTL_FACTORY/gen_rtl/iu/rtl/ct_iu_bju_pcfifo.v) 保存分支 PC、目标和预测检查快照，各 entry 对创建、完成和状态分别开钟。两者都在真正塞满前预留最大突发写入空间，因此可能牺牲少量瞬时容量来简化控制。功耗上，缓冲能平滑 cache 返回与译码消费的突发，避免每次短反压都立即停止再重启更前级；它也增加了指针、宽选择和驻留状态。应统计 IBUF/PCFIFO 水位、entry 写读次数、bypass 命中、full 反压和 flush 清除项数，才能判断缓冲是在吸收抖动，还是长期保存最终会被清掉的错误路径数据。

CP0 还分别输出 `cp0_ifu_bht_en`、`btb_en`、`l0btb_en`、`icache_en`、`icache_pref_en`、`ind_btb_en`、`lbuf_en` 和 `ras_en` 等功能使能。以 BHT 为例，`cp0_ifu_bht_en` 不仅屏蔽预测使用，也进入阵列读写和历史更新的门控条件，所以关闭功能确实能减少局部活动；其他结构也有各自的使能路径。不过，这些位是功能与诊断配置，不是“置零必然降低整机能量”的简单开关。关闭预测器可能减少一次预测访问，却增加误预测、错误路径执行和重取；关闭 I-cache 或预取可能减少本地阵列活动，却增加更远层次的数据搬运和执行时间。因此，合理的实验应同时比较被关闭结构的访问次数、总周期、退休指令、miss/误预测、平均功率和固定任务总能量，才能判断它是在转移功耗，还是确实减少了能量。

## 6. 乱序后端：不让“宽机器”在每个周期把所有状态都翻一遍

乱序超标量处理器的能耗困难来自宽度和窗口大小的乘法效应。每条完成结果都可能与多个 issue queue 源寄存器比较，每次分配都要寻找空表项并更新年龄关系，每次退休又会触及 ROB、PST 和释放向量。若把这些结构做成一个巨大的全相联窗口，比较器、选择树、广播线和长距离数据线会同时增加电容与延迟。C910 将整数、分支、访存和浮点/向量操作分配到 AIQ、BIQ、LSIQ、SDIQ、VIQ 等局部队列：AIQ 与 VIQ 的队列规模为 8 项，BIQ、LSIQ 和 SDIQ 为 12 项。分布式组织让每次唤醒选择主要在相关队列内完成，减小局部扇入和物理跨度，但代价是跨队列分配平衡、结果广播以及不同执行管线间的旁路仍需要全局协调。

以 [`ct_idu_is_aiq0_entry.v`](../C910_RTL_FACTORY/gen_rtl/idu/rtl/ct_idu_is_aiq0_entry.v) 为例，一个表项不是由单一“大时钟”驱动全部字段。entry 状态、create 数据、PCFIFO 信息、目的寄存器和源 ready 状态有各自使能条件；没有新建表项时，宽创建数据保持不动，只有匹配到广播的源 ready 位才需要变化。[`ct_idu_is_aiq0.v`](../C910_RTL_FACTORY/gen_rtl/idu/rtl/ct_idu_is_aiq0.v) 通过局部 age vector 选择最老 ready 指令，并允许在队列为空且 create0 已 ready 时走 create-to-issue bypass。后者的性能意义是新指令不必先写队列、下一周期再读出；功耗意义则更微妙：它可能省掉一次完整表项驻留与读取，但也增加了旁路选择逻辑。是否净节能取决于 bypass 使用率和新增组合网络电容，需要活动率分析确认。

整数物理寄存器文件是另一个典型例子。[`ct_idu_rf_prf_pregfile.v`](../C910_RTL_FACTORY/gen_rtl/idu/rtl/ct_idu_rf_prf_pregfile.v) 包含 96 个物理寄存器，其中 preg0 固定为零，其余寄存器由 [`ct_idu_rf_prf_gated_preg.v`](../C910_RTL_FACTORY/gen_rtl/idu/rtl/ct_idu_rf_prf_gated_preg.v) 逐项产生写时钟。三个 write-back 端口先把目的寄存器展开为 one-hot 命中，只让被写的 64 bit 寄存器更新。若所有 95 个可写寄存器共用一个写时钟，一次 write-back 会让数千个触发器时钟端翻转，即使绝大多数数据保持不变；逐寄存器门控把活动限制在真正的目的项。对应的代价是宽 one-hot 译码、较长的选择线以及大量小门控分支，这也是为什么最终收益必须结合布局后的线电容和门控树来评价。

ROB 和 PST 的设计也体现了“只更新发生状态转移的项”。[`ct_rtu_rob_entry.v`](../C910_RTL_FACTORY/gen_rtl/rtu/rtl/ct_rtu_rob_entry.v) 分开门控表项创建、完成和 LSU 完成相关字段；一个 ROB entry 最多可折叠记录三条 ISA 指令的完成计数，当前实现有 64 个物理 entry。折叠减少了每条简单指令都占用完整 ROB 元数据的需求，有利于面积和每条指令的状态能量，但会增加完成计数、异常归属和退休控制复杂度。[`ct_rtu_pst_preg_entry.v`](../C910_RTL_FACTORY/gen_rtl/rtu/rtl/ct_rtu_pst_preg_entry.v) 将物理寄存器状态组织为等待分配、已分配、已退休、待释放等生命周期，并仅在分配、退休、flush 或释放事件发生时改变相关项。体系结构上，它保障精确恢复；功耗上，它避免把整个映射状态表当作每周期更新的大寄存器堆。

这些机制共同说明，乱序核心的低功耗重点不是缩小单个 ALU，而是控制元数据的活动半径。窗口越大、宽度越高，依赖比较、年龄选择、资源分配和恢复状态的总电容越容易超过算术单元本身。C910 通过分布式队列、表项级门控、字段级门控、折叠 ROB 和按目的寄存器写入，把“机器理论上拥有的容量”与“本周期真正活动的容量”分开。评估时应该统计各队列有效项数、广播命中数、create/issue/retire 宽度和门控开启率，而不能只用队列总容量推断功耗。

## 7. LSU、D-cache 与 L2：减少数据搬运通常比减少一次逻辑运算更重要

64 bit 数据在多级 cache、队列、旁路和互连中移动时，会驱动长线和大阵列，能量往往显著高于一个局部布尔运算。C910 的 64 KiB、2 路 L1 D-cache 在 [`ct_lsu_dcache_top.v`](../C910_RTL_FACTORY/gen_rtl/lsu/rtl/ct_lsu_dcache_top.v) 中把 tag、dirty 和数据阵列分开，数据由八个 32 bit bank 组成。[`ct_lsu_dcache_data_array.v`](../C910_RTL_FACTORY/gen_rtl/lsu/rtl/ct_lsu_dcache_data_array.v) 为 bank 提供独立时钟使能，并把字节写掩码扩展到 bit 级 SRAM 写使能。窄 store 因而不必改写整条宽数据；没有访问请求的 bank 也不必活动。这里同时降低了字线/位线活动与无关数据翻转，并为 load/store 并行仲裁提供了更细的物理组织基础。

地址翻译本身也是存储层次的一部分，并且是此前容易被低估的能量来源。C910 的 [`ct_mmu_iutlb.v`](../C910_RTL_FACTORY/gen_rtl/mmu/rtl/ct_mmu_iutlb.v) 有 32 个寄存器表项，其中 0、8、16、24 是四个 fast slot；所有 32 项参与命中比较，但物理地址的快速读出只从四个 fast slot 选择，slow entry 命中后会与一个 fast slot 交换。这个设计主要缩短最终 PA 选择路径，并没有消除 32 项并行比较的动态功耗。数据侧 [`ct_mmu_dutlb.v`](../C910_RTL_FACTORY/gen_rtl/mmu/rtl/ct_mmu_dutlb.v) 有 16 个普通项和一个专用 1 GiB 页项，两个 LSU 查询端口都会形成相联比较。小型 uTLB 命中时，核心避免访问更大的 SRAM JTLB；其代价是相联比较、PLRU 更新和慢项提升仍会消耗局部能量。

uTLB miss 后，请求进入 [`ct_mmu_jtlb.v`](../C910_RTL_FACTORY/gen_rtl/mmu/rtl/ct_mmu_jtlb.v) 的 256 组×4 路 JTLB。JTLB 只在请求、未完成读、PFU 或回填等活动存在时打开本地时钟，tag SRAM 的 CEN 由实际仲裁请求产生，data SRAM 又分成两组 CEN。由于 4 KiB、2 MiB、1 GiB 页混存在同一结构，普通虚地址查询会先按 4 KiB 候选索引，未命中再按 2 MiB、最后按 1 GiB 查询；最坏情况下，一次 uTLB miss 会引发三次 JTLB 访问。三种候选都 miss 时，[`ct_mmu_ptw.v`](../C910_RTL_FACTORY/gen_rtl/mmu/rtl/ct_mmu_ptw.v) 才打开自己的门控时钟，按 Sv39 最多读取三级页表项，而且没有独立 PTE cache，每次 PTE 读取都经 LSU，可能命中 D-cache，也可能继续进入 RB、BIU 和更远存储层次。这形成一条清楚的能量放大链：uTLB hit 只活动小表；uTLB miss 活动 JTLB；JTLB miss 又活动 PTW、cache、互连和外部存储。评价 MMU 功耗时，应按“在哪一层命中”和“页表读取落在哪一级 cache”分解事件，单看最终 TLB miss 数无法解释真实能量。

LSU 中的 LQ、SQ、WMB、RB、LFB、VB 等队列不仅用于性能，也改变能量路径。store 可以先进入 SQ/WMB，体系结构退休不必等待下层存储立即完成；load miss 可以由 refill buffer 跟踪，核心继续执行其他独立指令。这样可能缩短总运行时间并隐藏外部高能耗访问的延迟，但队列本身有比较、地址匹配和转发成本。尤其 load 为获得正确值，需要在 cache 数据、store queue 和 write merge buffer 之间做字节级选择；窗口更大虽然提高发现并行性的机会，也扩大地址比较和转发网络。C910 的设计通过有限容量和分模块队列把复杂度控制在可实现范围内，而不是无限扩大一个统一 memory order buffer。

硬件预取体现了功耗与性能不可分割的双刃剑。[`ct_lsu_pfu.v`](../C910_RTL_FACTORY/gen_rtl/lsu/rtl/ct_lsu_pfu.v) 维护预取状态，在低功耗 no-op 请求期间阻止继续产生工作，并以 64 字节 cache line、四个 128 bit beat 的方式跟踪传输；[`ct_lsu_pfu_pmb_entry.v`](../C910_RTL_FACTORY/gen_rtl/lsu/rtl/ct_lsu_pfu_pmb_entry.v) 对条目使用局部门控，而且创建后并不立即 ready：第一次再次观察到同一 PC 时只把一位计数置 1，第二次同 PC 命中才把 entry 置为 ready。也就是说，它用两次重复行为确认过滤偶发地址流，再允许后续预取机制使用该模式。一个有用预取可以把未来 demand miss 变成 hit，减少核心停顿和整体执行时间；一个无用预取则消耗 L1/L2/总线活动、污染 cache 并挤占真正请求。因而预取功耗不能只在 PFU 模块内衡量，而应同时观察 useful、late、useless、pollution 以及额外总线字节数，并最终比较固定任务的总能量。

共享 L2 当前配置为 1 MiB、16 路组相联，并拆为两个 sub-bank。[`ct_l2c_top.v`](../C910_RTL_FACTORY/gen_rtl/l2c/rtl/ct_l2c_top.v) 分别实例化两个 sub-bank；[`ct_l2c_sub_bank.v`](../C910_RTL_FACTORY/gen_rtl/l2c/rtl/ct_l2c_sub_bank.v) 只在新请求或本 bank 仍 busy 时打开本地 `l2c_clk`；[`ct_l2c_tag.v`](../C910_RTL_FACTORY/gen_rtl/l2c/rtl/ct_l2c_tag.v) 和 [`ct_l2c_data.v`](../C910_RTL_FACTORY/gen_rtl/l2c/rtl/ct_l2c_data.v) 又分别控制 tag/status 与 data SRAM 的时钟和 CEN。分 sub-bank 的首要电路意义是一次请求不必让整个 1 MiB 结构的控制和数据路径同时活动，也可减少局部线长；16 路相联则意味着 tag compare 和状态判断具有较大的并行活动范围。容量、相联度、冲突 miss、tag 能量和物理线长之间没有脱离工作负载的绝对最优点。

CIU 的请求按地址 bit 6 路由到两个 snoop node bank，可在 [`ct_piu_top.v`](../C910_RTL_FACTORY/gen_rtl/ciu/rtl/ct_piu_top.v) 的 `ibiu_ciu_araddr[6]` 与 `ibiu_ciu_awaddr[6]` 选择中直接看到。64 字节 cache line 的 bit 6 在相邻 line 间变化，因此这种交织让连续 cache line 分散到两个 bank，既增加并行机会，也缩小每个 bank 的一致性跟踪范围。功耗上，它减少单一中心节点的扇出和拥塞，却增加了双 bank 的固定控制与泄漏。最终是否更省能量取决于并发访问、snoop 流量和物理布局，但 RTL 清楚表达了通过分区而非单体结构承载共享层次的思路。

这里还必须说明当前公开生成配置的 ECC 边界。在 [`ct_lsu_ld_da.v`](../C910_RTL_FACTORY/gen_rtl/lsu/rtl/ct_lsu_ld_da.v) 中，八个 32 bit D-cache ECC decoder 实例被注释，`ld_da_ecc_stall`、`ld_da_lm_ecc_err`、`ld_da_ecc_spec_fail` 等信号固定为零；[`ct_l2cache_top.v`](../C910_RTL_FACTORY/gen_rtl/l2c/rtl/ct_l2cache_top.v) 中 tag、dirty 和 data ECC array 实例同样被注释，[`ct_l2c_wb.v`](../C910_RTL_FACTORY/gen_rtl/l2c/rtl/ct_l2c_wb.v) 又把 fatal error 固定为零、把 ECC response FIFO 视为恒空。因而，名字中出现 ECC 或状态机保留 ECC 分支，只能说明生成模板预留过接口，不能证明本配置执行了完整纠错。当前配置的功耗分析不应虚构 ECC 存储位、编码器和纠错写回的活动；若在产品配置中恢复 ECC，则必须重新计入冗余 bitline、读出 syndrome、纠错选择、scrub/回写和错误重放的能量，同时重新验证故障注入确实能到达架构可见错误处理。

## 8. 计算单元：流水化、迭代和时钟门控共同决定每次运算的代价

复杂算术单元既有大量组合门，也容易产生内部毛刺。把长组合路径切成流水级，可以缩短每一级逻辑深度，并让寄存器阻断跨级毛刺传播；但新增寄存器和时钟负载会增加每次操作的固定能量，所以“流水级越多越省电”并不成立。C910 的浮点乘加控制 [`ct_vfmau_ctrl.v`](../C910_RTL_FACTORY/gen_rtl/vfmau/rtl/ct_vfmau_ctrl.v) 明确组织了 EX1 到 EX5 的有效状态，并分别为 EX1→EX2、EX2→EX3、EX3→EX4、EX4→EX5 生成门控时钟。没有 FMA/乘法操作穿过某一级时，对应级的控制和数据寄存器可以保持静止。这样，深流水为高频提供逻辑边界，逐级有效门控又避免空流水泡仍让所有寄存器翻转。

整数乘法器 [`ct_iu_mult.v`](../C910_RTL_FACTORY/gen_rtl/iu/rtl/ct_iu_mult.v) 将 65×65 乘法的计算跨 EX1 到 EX3 推进，并在 EX4 寄存与选择最终 64 bit 结果；整数除法器 [`ct_iu_div.v`](../C910_RTL_FACTORY/gen_rtl/iu/rtl/ct_iu_div.v) 和浮点除法/开方控制 [`ct_vfdsu_ctrl.v`](../C910_RTL_FACTORY/gen_rtl/vfdsu/rtl/ct_vfdsu_ctrl.v) 则采用迭代 SRT 状态机。迭代结构重复使用同一组算术硬件，避免将每一轮完全展开为巨大的组合网络，因此通常有利于面积、峰值电容和可达频率；代价是单条除法占用单元多个周期，依赖链延迟更长、吞吐有限。对于除法稀少的通用程序，这是常见的合理取舍；若工作负载除法密集，较长运行时间和单元持续活动可能抵消局部面积/功耗优势。只有把操作分布与忙周期纳入分析，才能评价该取舍是否适合目标场景。

## 9. 示例 UPF 与 PMU 展示了更深低功耗，但不等同于核心 RTL 实现

仓库的 [`example_cpu_power_spec.upf`](../smart_run/impl/upf/example_cpu_power_spec.upf) 定义了 `PD_TOP` 与 `PD_CPU`，为 CPU 域建立受控的 `VDD_CPU_SW`，并描述输入/输出隔离、低电平 clamp、retention save/restore 以及 top-on/cpu-off 电源状态。配套示例 [`pmu.v`](../smart_run/logical/pmu/pmu.v) 用计数状态安排深睡进入顺序：先拉起隔离，再产生保存脉冲，最后关闭 CPU 电源；退出时先恢复供电，再产生 restore 脉冲，最后解除隔离。顺序背后的物理原因很清楚：断电前先隔离可阻止掉电域输出变成 X 或中间电平污染常开域；状态保存必须发生在电源消失前；上电后要等待电源和保持状态稳定，才能解除隔离让信号重新参与系统功能。

不过，这些文件位于 `smart_run` 的实现示例路径，PMU 也是示例 SoC 逻辑，不等同于 `C910_RTL_FACTORY/gen_rtl` 内部已经具有完整 power-gating 网络。UPF 中 power switch 的 off-state 描述还有注释状态，而电源状态表又列出 CPU off，实际实现前需要做一致性审查、UPF lint、低功耗仿真以及 isolation/retention 检查。严谨的结论是：C910 核心 RTL 提供了排空和停钟所需的低功耗协议；仓库另附一个可用于探索 CPU 域断电、隔离和保持的实现框架。要宣称完整的深度休眠，需要把二者在具体 SoC、标准单元库和 P&R 流程中真正连接并验证。

## 10. 功耗、频率和面积必须一起收敛

低功耗优化经常向时序施加反向压力。更小驱动单元、较高阈值电压和更少缓冲通常降低动态功耗或泄漏，却让路径变慢；复制寄存器、增加缓冲和使用低阈值单元可修复高扇出与关键路径，却增加面积、泄漏和开关电容。时钟门控减少活动，但门控使能本身要在时钟边沿前稳定；更细粒度的 bank 与表项门控减少数据活动，却增加控制译码和布线。因此，可靠流程不是先追求最高频率再“做低功耗”，也不是只按 RTL 门控数量评价，而是让性能、功耗、面积在相同工艺角、约束和工作负载下迭代。

平均功耗之外，还必须检查同一小段时间内有多少电路同时开关。多路 write-back 与广播、cache refill 的宽数据传输、误预测后重新填充流水线、WFI 唤醒以及 scan capture，都可能形成短时电流峰值。电源网络的电阻产生近似 `I·R` 压降，封装和片上电感又会对快速 `di/dt` 产生额外 droop；局部 `V_DD` 降低后晶体管过驱动变小，关键路径恰好在高活动时变慢，于是功耗完整性直接反馈到时序。细粒度门控能降低长期平均活动，却不保证较低峰值：若大量门控分支在同一拍同时打开，瞬态甚至可能更尖锐。当前 RTL 可以指出哪些事件会同时唤醒大批状态，却不能证明供电网络、去耦电容和热分布已经满足要求；这需要布局后的 vector-based dynamic IR-drop、EM 和热分析。尤其应把稳定 benchmark、cache/TLB 维护、睡眠唤醒和扫描测试分成不同活动场景，而不能用一份平均 SAIF 同时替代它们。

后端脚本 [`dc.tcl`](../backend/syn/ct_top/v1-dc/global_scripts/dc.tcl) 表达了这种联合优化的入口：可配置 `set_clock_gating_style` 和 `compile_ultra -gate_clock`，也可打开 `set_leakage_optimization` 与 `set_dynamic_optimization`，并生成 timing、power、area、clock-gating 和 threshold-voltage 报告。它还将综合 cost priority 设为 delay，说明该流程的首要约束仍是时序。脚本具备选项不代表每次现有结果都已正确启用。仓库当前 [`MultiVt.rpt`](../backend/syn/ct_top/v1-dc/reports/MultiVt.rpt) 把所有单元都列为 `undefined` Vth group，所以不能用它证明 HVT/SVT/LVT 的实际比例；若要研究泄漏与频率平衡，应先修复库的 threshold-voltage 分组和报告识别，再比较关键路径上的 LVT 使用与非关键区 HVT 覆盖率。

## 11. 怎样对 C910 做可信的功耗验证

第一步是定义同一份有用工作，而非只规定仿真周期数。对于 CoreMark、Dhrystone 或 representative kernel，应固定二进制、输入、迭代次数、初始 cache/预测器状态和结束条件，记录退休指令数与总周期。RTL 仿真生成的 FSDB/VCD 可转换为 SAIF，或直接在支持的功耗工具中回标活动率。要覆盖启动、预热、稳定区间和退出中的哪一段必须写清楚；若只研究稳态微结构，应从已经进入目标 kernel 的窗口取样，但总任务能量还要把不可忽略的初始化计入。至少报告平均功耗、动态/泄漏分量、总能量、每退休指令能量，以及各层 cache 和主要模块的占比。

第二步是让网表、库和活动率彼此匹配。综合或门级网表应使用实际映射的 ICG 与 SRAM 宏，SRAM 需要内部读写能量和 leakage 模型，而不能仅按黑盒端口电容估计。时钟应使用真实频率；布局前估算只能作为相对筛选，布局后应回标 SPEF/寄生并使用 CTS 后时钟树。PVT 至少覆盖目标工作角和高温泄漏角，若存在多电压状态则分别计算。组合毛刺对动态功耗有影响，零延迟传播通常会漏掉它，因此关键结论最好用门级带延迟活动或工具的时序感知功耗分析复核。

第三步是验证门控本身。应统计每个层级门控时钟的开启占空比、下游寄存器数量和平均连续关闭长度，而不只是 ICG 数量；短到一两个周期的细门控可能收益有限，长空闲段更值得关注。功能验证要覆盖门控开关边界、scan bypass、WFI 进入/退出、各类中断、调试请求、snoop 唤醒和 no-op 排空，确保没有脉冲截断、漏时钟或唤醒死锁。还应以 `MHINT2[22:14]` 逐模块强制开钟做对照：若某位从 0 改为 1 后功能变化，说明局部门控条件或跨门控协议可能有错误；若功能不变但功耗几乎不变，则要检查该模块本来就持续繁忙、ICG 未映射，或功耗工具没有回标真实活动。实现验证还要运行 clock-gating setup/hold 检查、生成时钟检查和 CDC/RDC 分析。对示例 power gating，则另需验证掉电期间隔离、retention save/restore、X 传播和电源状态转换。

复位、扫描和 cache/TLB 维护要作为独立功耗阶段处理。异步复位释放会同时唤醒大量状态，cache/TLB invalidate 或 L2 flush 会连续扫描、读写多个表项，扫描模式下 `pad_yy_icg_scan_en` 又会绕过功能门控，使原本互斥的寄存器群在 shift 时高频翻转；它们都不代表稳态程序活动，却可能决定峰值电流、IR drop 和测试热风险。报告正常 benchmark 功耗时可把这些阶段与稳定 kernel 窗口分开，但评估启动能量、休眠唤醒或 DFT 时不能删除它们。扫描功耗还应使用实际 shift/capture 频率与 ATPG 活动，而不能把功能模式 SAIF 直接套到 scan 模式。

仓库现有 [`power.rpt`](../backend/syn/ct_top/v1-dc/reports/power.rpt) 可以作为“为什么不能直接相信默认功耗数值”的反例。报告开头明确警告 primary input、顺序单元输出和 black-box 输出缺少活动率回标，并采用 low-effort、zero-delay activity propagation；其层次结果又把约 95.4% 总功率归到 `ct_clk_top`，其中通用 `BUFGCE` 模型占绝大部分。这与宏模型、活动率和时钟建模方式强相关，不能当作 C910 的真实功耗或模块占比。正确用法是先修正顶层时钟模型和 ICG 识别，回标代表性程序活动，确认 SRAM 宏功耗弧，再把该报告变成相对比较基线。任何 RTL 优化都应与完全相同的基线脚本和活动窗口比较，并同时检查性能没有退化。

## 12. 从这些 RTL 例子得到的总体认识

C910 的功耗设计主线可以归纳为“只让当前有用工作的最小必要电路活动”。长时间系统空闲时，CP0 先让 IFU、LSU、BIU 和 MMU 达到可冻结状态，再关闭正常核心时钟，同时保留中断、调试和一致性唤醒通道；模块工作但局部无事件时，统一 ICG 封装关闭流水级、表项或字段时钟；前端通过分层分支预测、way prediction、tag 复用、bank CEN、loop buffer 与 IBUF/PCFIFO 的按项更新缩小预测、取指和缓冲活动；地址翻译通过 uTLB、门控 SRAM JTLB 和仅在 miss 时工作的 PTW，把常见命中的活动限制在较小层次；乱序后端通过分布式队列、按项状态更新、物理寄存器 one-hot 写入和 ROB 折叠避免让机器的全部容量每周期翻转；长延迟算术单元则用流水级门控或迭代复用平衡频率、面积和每次操作能量。

这些机制不是互不相关的技巧。分支预测和 loop buffer 减少错误或重复工作，降低的是整个流水线的无效活动；队列和旁路提高并行度，可能增加瞬时功耗，却能缩短固定任务的执行时间；更深门控减少动态功耗，却可能增加使能时序与 CTS 难度；更深 power-off 能降低泄漏，却需要隔离、保持和更长恢复。真正的低功耗设计因此是体系结构效率、微结构活动控制、电路实现和软件工作负载共同决定的结果。RTL 给出了 C910 如何组织这些机制的可核查证据，最终收益则必须通过同一工作量下的时序闭合、活动率回标、布局后功耗和性能数据来完成证明。
