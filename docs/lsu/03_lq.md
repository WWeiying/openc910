# C910 Load Queue 详解（ct_lsu_lq）

> RTL 源文件：`ct_lsu_lq.v`（979 行）+ `ct_lsu_lq_entry.v`（约 470 行）×16
>
> LQ 是乱序访存正确性的"监控摄像头"：记录每条**已经拿到数据**的 load，
> 供后来的 store（RAW）和 load（RAR）反查"我是不是被人抢跑了"。

---

## 1. 为什么需要 LQ

C910 允许 load 乱序执行（只要 SQ 里没有发现重叠的老 store 就放行）。
两种赌局可能输：

| 违例 | 场景 | 后果 |
|------|------|------|
| **RAW**（load 越过老 store） | store 地址当时还没算出来，load 先跑了 | load 读到旧值 |
| **RAR**（load 越过老 load，多核场景） | 两个同地址 load 乱序，中间夹了外部核的写（snoop） | 新 load 读到旧值、老 load 读到新值——违反同地址读序（coherence 要求） |

输了的标志：**后到的老指令在 DC 级反查 LQ 时发现重叠的年轻项**。

## 2. 表项内容与比较逻辑（lq_entry.v）

每项记录：PA、`bytes_vld[15:0]`、iid、有效位。

### RAR 检查（lq_entry.v:290-322，由 ld_dc 的 load 发起）

```verilog
// 地址按 16B 粒度比较（PA_WIDTH-1:4）+ 字节位图相交
assign lq_entry_rar_addr_tto4_hit = (entry_pa[39:4] == ld_dc_pa[39:4]);
assign lq_entry_rar_do_hit  = |(lq_entry_bytes_vld & ld_dc_bytes_vld);   // L303
assign lq_entry_rar_spec_fail0 = lq_entry_newer_than_ld_dc    // 我(表项)比来查的更年轻
                              && ld_dc_inst_chk_vld
                              && addr_hit && do_hit;          // L307-310
```

`newer_than_ld_dc` 用 compare_iid（doc/rtu/07）判年龄。注意检查方向：
**表项是先跑的年轻 load，来查的是后到的老 load**——老 load 现在才执行，
说明年轻 load 当时的数据可能已经过期（中间可能有 snoop 改写）。
`cp0_lsu_corr_dis`（L321-322）可全局关掉 RAR 检查（单核场景不需要）。

非对齐双段访问有独立的 addr1 比较组（spec_fail1，L312-316）。

### RAW 检查（lq_entry.v:325 起，由 st_dc 的 store 发起）

同构：store 的 PA/bytes_vld 与每个**比它年轻**的 LQ 项相交 → raw_spec_fail。

## 3. 违例之后发生什么

LQ 命中只产生一个标记，处理链条很长：

```
lq_entry_raw/rar_spec_fail
  → 汇总到 ld_da/st_da 的完成信息 lsu_rtu_wb_pipe3/4_spec_fail
  → RTU 异常擂台（doc/rtu/03，与真异常同走单项缓冲，expt_vld=0）
  → 违例指令退休时 flush（spec_fail_flush + spec_fail_iid 通报 LSU）
  → 从违例 load 处重取重执行，这次 SQ 里已有正确数据 → 前递成功
  → 同时训练 spec_fail_predict（10_misc.md）：该 load 下次不再抢跑
```

代价 = 一次完整 flush（几十拍），所以 perf 里 `LSU Spec Fail 169` 次
对 489K 周期的影响约 1~2%。预测器存在的意义就是把这个数字压低。

## 4. 顶层逻辑（ct_lsu_lq.v）

- 16 项，**两个创建口**（pipe3 load 每拍一条 + 非对齐第二段），创建指针
  逻辑 L878-963；
- 弹出：load 指令**退休即可释放**（它的"被反查窗口"= 在飞期）；flush 清
  推测项；
- `lq_ld_dc_full`（L966）：满则 load 在 DC restart——LQ 满是 load 密集代码
  的隐性瓶颈之一。

## 5. 与教科书的对照

经典 LSQ 把 load/store 放一个队列做 CAM；C910 拆成 LQ（监控）+ SQ（前递）
两个职责单一的结构：LQ 不存数据只存地址位图（窄），SQ 才存数据（宽）。
**比较都是 16B 粒度 + 字节位图**，比全地址 CAM 便宜，代价是 16B 粒度的
假阳性（同 16B 不同字节 → bytes_vld 相交兜底，仍精确；不同 16B 必不相交）。

## 6. Verdi 观察建议

层次：`...x_ct_lsu_top.x_ct_lsu_lq.x_ct_lsu_lq_entryN`

| 信号 | 看什么 |
|------|--------|
| `lq_entry_vld` ×16 | LQ 水位 |
| `lq_entry_raw_spec_fail_x / rar_spec_fail_x` | 违例抓现行 |
| 顶层 `lq_ld_dc_full` | 满反压 |
| 配合 `rtu_lsu_spec_fail_iid` | flush 归因到哪条 load |

构造违例：store 的地址依赖一个慢 load（如先 load 算地址再 store），
紧跟一个同地址 load——年轻 load 必抢跑，st_dc 到达时必抓到。
